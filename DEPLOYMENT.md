# Retainr GitHub Pages Cutover

This runbook moves `www.retainr.io` from Webflow to the Astro site in `Retainr/website` with a reversible, low-downtime DNS change.

## Production ownership

- Canonical site: `https://www.retainr.io`
- Apex redirect: `https://retainr.io` to `https://www.retainr.io`
- Repository: `https://github.com/Retainr/website`
- Publishing branch: `main`
- Build output: `dist/`
- Deployment: `.github/workflows/deploy.yml`
- DNS provider: Cloudflare

The repository already contains `public/CNAME` with `www.retainr.io`, `public/.nojekyll`, a custom `404.html`, `robots.txt`, `sitemap.xml`, and `llms.txt`.

## Current DNS snapshot

Verified on 8 August 2026:

| Name | Type | Current value | Purpose |
| --- | --- | --- | --- |
| `@` | `A` | `198.202.211.1` | Webflow apex |
| `www` | `CNAME` | `cdn.webflow.com` | Webflow website |
| `@` | `MX` | Cloudflare Email Routing records | Retainr email |

Only replace the first two website records. Do not change MX, TXT, CAA, NS, `app`, `api`, `status`, `ambassador`, `careers`, `help`, or any other subdomain.

## Phase 1: Prepare GitHub without changing traffic

1. Confirm the repository is eligible for GitHub Pages. Public repositories work with GitHub Free. A private organization repository requires a GitHub plan that includes private Pages.
2. Open `https://github.com/Retainr/website/settings/pages`.
3. Under **Build and deployment**, set **Source** to **GitHub Actions**.
4. Push the reviewed `main` branch:

```bash
cd /Users/pierre/Code/Retainr/website
git status --short --branch
npm ci
npm run build:ci
git push origin main
```

5. Open the repository's **Actions** tab and confirm **Deploy to GitHub Pages** completes successfully.
6. Open the deployment summary and confirm both `build` and `deploy` are green. Do not change DNS after a failed or cancelled run.

The workflow uses Astro's official Pages action, the committed npm lockfile, Node 24, the production build, and `scripts/verify-build.mjs`. The verifier rejects broken internal links, missing discovery files, missing canonicals, missing Crisp chat, or retired plan/trial signup language.

## Phase 2: Verify domain ownership

Complete this before pointing DNS at GitHub. It prevents another GitHub account from claiming the domain.

1. In GitHub, open the **Retainr organization**.
2. Go to **Settings → Pages → Add a domain**.
3. Enter `retainr.io`.
4. GitHub will provide a TXT record resembling:

```text
Name:  _github-pages-challenge-Retainr
Type:  TXT
Value: <value generated by GitHub>
```

5. In Cloudflare, open **DNS → Records** for `retainr.io` and add the exact TXT value GitHub generated.
6. Verify it publicly:

```bash
dig @1.1.1.1 _github-pages-challenge-Retainr.retainr.io TXT +short
```

7. Return to the Retainr organization Pages settings and click **Verify**.
8. Keep this TXT record permanently. Do not remove it after launch.

Do not create wildcard DNS records. GitHub explicitly warns that wildcards increase custom-domain takeover risk.

## Phase 3: Register the production hostname

1. Return to `https://github.com/Retainr/website/settings/pages`.
2. Under **Custom domain**, enter `www.retainr.io` and click **Save**.
3. Leave **Enforce HTTPS** off only while GitHub is waiting for DNS and its certificate. Enable it as soon as GitHub makes the option available.

Register the custom domain in GitHub before changing DNS. This is GitHub's recommended order and prevents a hostname claim gap.

## Phase 4: Lower DNS TTL

Ideally do this at least 24 hours before the cutover:

1. In Cloudflare DNS, change the TTL for the `@` website record and the `www` record from the current 3600 seconds to 300 seconds.
2. Ensure both records are **DNS only** (grey cloud) during GitHub validation and certificate issuance.
3. Leave every non-website record unchanged.

If the cutover must happen immediately, continue. Existing resolvers may keep Webflow for up to the current one-hour TTL, which is acceptable because Webflow remains online during propagation.

## Phase 5: Change the two website records

Take a screenshot or export of the Cloudflare DNS zone first.

### Remove

| Name | Type | Value |
| --- | --- | --- |
| `@` | `A` | `198.202.211.1` |
| `www` | `CNAME` | `cdn.webflow.com` |

### Add

| Name | Type | Value | Proxy | TTL |
| --- | --- | --- | --- | --- |
| `@` | `A` | `185.199.108.153` | DNS only | 300 |
| `@` | `A` | `185.199.109.153` | DNS only | 300 |
| `@` | `A` | `185.199.110.153` | DNS only | 300 |
| `@` | `A` | `185.199.111.153` | DNS only | 300 |
| `www` | `CNAME` | `retainr.github.io` | DNS only | 300 |

The `www` target must be exactly `retainr.github.io`. Do not append `/website`, a protocol, or a trailing path.

GitHub also publishes optional IPv6 records. Add them only if IPv6 is intentionally supported and monitored:

```text
2606:50c0:8000::153
2606:50c0:8001::153
2606:50c0:8002::153
2606:50c0:8003::153
```

The existing CAA policy already permits Let's Encrypt. Do not delete or replace the current CAA records.

## Phase 6: Verify DNS and HTTPS

Run these checks against a public resolver:

```bash
dig @1.1.1.1 retainr.io A +short
dig @1.1.1.1 www.retainr.io CNAME +short
```

Expected results:

- Apex returns all four `185.199.*.153` GitHub Pages addresses.
- `www` returns `retainr.github.io.`

Then check HTTP behavior:

```bash
curl -sSIL https://retainr.io/
curl -sSIL https://www.retainr.io/
curl -sSIL https://www.retainr.io/pricing/
curl -sSIL https://www.retainr.io/blog/
curl -sSIL https://www.retainr.io/compare/
curl -sSIL https://www.retainr.io/niches/
curl -sSIL https://www.retainr.io/privacy-policy/
curl -sSIL https://www.retainr.io/whilte-label-agency-management-software/
curl -sS https://www.retainr.io/robots.txt
curl -sS https://www.retainr.io/sitemap.xml | head
```

Expected behavior:

- `https://www.retainr.io/` returns `200`.
- `https://retainr.io/` redirects to `https://www.retainr.io/` after GitHub recognizes both DNS variants.
- All sampled canonical pages return `200`.
- The historical misspelled white-label URL remains reachable and forwards visitors to the canonical route.
- `robots.txt` advertises `https://www.retainr.io/sitemap.xml`.
- The sitemap contains the home, pricing, blog, comparison, and niche directories.

In GitHub repository **Settings → Pages**, wait for the DNS check to pass, then enable **Enforce HTTPS**. GitHub notes that certificate availability can take up to 24 hours.

## Phase 7: Visual production sweep

Check the live site in a private browser window at desktop and mobile widths:

1. Header navigation opens, closes, and fits at 320 px.
2. Home dashboard image and fonts load without mixed-content errors.
3. Pricing says free forever and contains no plan selector.
4. One niche CTA reaches `https://app.retainr.io/signup?niche=<slug>`.
5. One comparison table stacks correctly on mobile.
6. Blog images and related-reading links are readable.
7. Crisp appears on content pages.
8. Login and signup still open `app.retainr.io`.
9. Status and affiliate links still reach their independent services.
10. Browser developer tools show no failed first-party assets or console errors.

## Phase 8: Search and analytics checks

The hostname and URLs remain unchanged, so this is a hosting migration rather than a domain migration.

1. In Google Search Console, inspect the home page plus one blog, niche, and comparison URL.
2. Resubmit `https://www.retainr.io/sitemap.xml`.
3. Confirm Google can fetch `robots.txt` and the canonical URL is the inspected URL.
4. Repeat sitemap submission in Bing Webmaster Tools.
5. Confirm signup-intent events still arrive in the existing first-party analytics destination.
6. Monitor indexing, 404s, Core Web Vitals, and signup clicks daily for the first seven days.

Do not change URL slugs, page titles, canonicals, or the `www` preference during the hosting cutover. Separate changes make diagnosis and rollback harder.

## Phase 9: Retire Webflow safely

Keep the Webflow site and its paid Site plan available for at least seven days as rollback insurance.

After seven stable days:

1. Export or archive the final Webflow project and billing records.
2. In Webflow, open **Site settings → Publishing → Production**.
3. Remove `retainr.io` and `www.retainr.io` from the Webflow site.
4. Confirm GitHub Pages remains healthy after removal.
5. Cancel or downgrade the Webflow Site plan if it is no longer needed.

Removing the Webflow domain is cleanup, not part of the traffic cutover. Do it after GitHub has proven stable.

## Rollback

Rollback is a DNS-only change while the Webflow project remains connected.

1. In Cloudflare, remove the four GitHub apex `A` records.
2. Restore:

```text
@     A       198.202.211.1
www   CNAME   cdn.webflow.com
```

3. Keep the records DNS only with TTL 300 during recovery.
4. Verify Webflow again with `dig` and `curl`.
5. Diagnose GitHub separately. Do not delete the repository, verification TXT record, or deployment history during an incident.

Rollback immediately if the new public DNS resolves to GitHub but the home page or critical routes fail, HTTPS cannot be established, or first-party assets consistently return errors.

## Normal release procedure

After cutover, every push to `main` deploys automatically:

```bash
cd /Users/pierre/Code/Retainr/website
git pull --ff-only origin main
npm ci
npm run build:ci
git push origin main
```

Watch the **Deploy to GitHub Pages** workflow before treating the release as complete. The deploy job depends on a successful verified build, so a failed build does not replace the previously published site.
